# Alles — 위키 백과사전 스타터

남색·금색 고전 백과사전 디자인과 위키형 문서 페이지를 갖춘 정적 프런트엔드 + Supabase 프로젝트입니다.

## 포함 기능
- 문서별 페이지 주소: `/alles/w/세종대왕` 형태의 SPA 경로
- 문서 작성·편집, 여러 카테고리 선택
- 이미지 업로드/이미지 URL, 홈페이지 링크, YouTube 영상 링크 및 영상 파일 첨부
- 문서별 토론과 신고
- 관리자 화면: 신고 처리, 보호 문서 수정 검토, 삭제 문서 복구, 권한 변경
- 삭제 보관 및 관리자 복구, 편집 역사와 이전 버전 복구 UI
- Alles 전용 `alles_` 테이블 이름으로 OSCADIA 기존 테이블과의 이름 충돌 방지

## 1. Supabase 연결
1. OSCADIA에서 사용하는 Supabase 프로젝트를 열고 Project URL과 publishable/anon key를 확인합니다.
2. `app.js` 위쪽의 `SUPABASE_URL`, `SUPABASE_ANON_KEY` 값을 입력합니다. `service_role` 키는 절대 넣지 마세요.
3. Supabase SQL Editor에서 `supabase-schema.sql`을 검토한 뒤 실행합니다. 기존 프로젝트의 다른 테이블은 삭제하거나 수정하지 않습니다.
4. Storage에 `alles-media` 버킷이 생성됐는지 확인합니다.

## 2. 관리자 계정
1. 웹사이트에서 회원가입하고 이메일 인증을 완료합니다.
2. Supabase SQL Editor에서 마지막 ADMIN SETUP 주석의 SQL을 복사하고 `YOUR_EMAIL_HERE`를 실제 계정 이메일로 바꿔 실행합니다.
3. 새로 로그인하면 관리자 버튼이 표시됩니다.

## 3. 페이지 경로 / 배포
프런트엔드는 SPA 방식으로 `/alles/w/<slug>` 경로를 처리합니다. 호스팅은 `/alles/*` 요청을 `index.html`로 rewrite/fallback 하도록 설정해야 직접 주소 접속과 새로고침이 작동합니다. GitHub Pages는 임의 경로 rewrite를 기본 지원하지 않으므로, 단순 폴더 업로드만으로는 `/alles/w/세종대왕` 직접 접속이 404가 될 수 있습니다. 이 경우 정적 호스팅의 rewrite 설정을 지원하는 배포처를 쓰거나, 프로젝트에 맞는 404 fallback을 추가해야 합니다.

## 중요 사항 / 현재 스타터의 한계
- 이 파일은 통합용 시작 버전이며 실제 Supabase 프로젝트에 연결해 SQL/RLS와 업로드를 테스트해야 합니다.
- 관리자 권한은 `alles_user_roles` 테이블의 `admin` 역할로 판정됩니다. 권한 변경 화면은 관리자 전용입니다.
- 삭제는 `deleted_at`으로 보관하고 관리자 화면에서 복구합니다. 영구 삭제는 복구할 수 없으므로 확인 대화상자를 표시합니다.
- 동영상 파일은 25MB 제한입니다. 더 큰 동영상은 YouTube 등 외부 동영상 링크 사용을 권장합니다.
- 사용자 프로필, 댓글 답글/스레드, 고급 위키 문법, 문서 이동/리다이렉트, 검색엔진 최적화는 아직 고도화 대상입니다.
- RLS 정책은 프로젝트별 설정과 기존 정책의 영향을 받을 수 있습니다. 운영 전에 테스트 계정으로 익명 열람, 회원 편집, 보호 문서 제안, 관리자 기능을 검증하세요.
